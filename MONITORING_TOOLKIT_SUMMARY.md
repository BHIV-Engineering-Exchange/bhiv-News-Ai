## Deliverables

### 1. **monitor_backend.py** – System Health Monitor
**Purpose**: Real-time backend availability and latency tracking

**Features**:
- ✓ Checks 6 critical endpoints every 30 seconds (configurable)
- ✓ Measures latency (flags if >2000ms)
- ✓ Detects HTTP errors and connection failures
- ✓ Appends errors to `newsai_error_log.json` (append-only log)
- ✓ Generates health status: HEALTHY | DEGRADED | CRITICAL
- ✓ Can run continuously or for N iterations

**Usage**:
```bash
# Continuous monitoring
python monitor_backend.py

# Monitor for 5 checks then exit
python monitor_backend.py --iterations 5

# Change interval to 60 seconds
python monitor_backend.py --interval 60

# Generate report
python monitor_backend.py --report
```

**Exit Codes**:
- 0: Monitoring completed
- 1: Error occurred

**Monitored Endpoints**:
- **Critical** (must be healthy): `/`, `/health`
- **Operational** (should be healthy): `/api/unified-news-workflow`, `/api/scrape`, `/api/summarize`, `/api/vet`

### 2. **demo_check.py** – Pre-Demo Safety Checker
**Purpose**: Validate system is ready for demonstration

**Features**:
- ✓ Runs 5 critical checks

**Usage**:

**Exit Codes**:

### 3. **newsai_error_log.json** – Append-Only Error Log
**Purpose**: Record all system failures and issues for post-demo analysis

**Format**: JSON array of error entries

**Entry Fields**:
```json
{
  "timestamp": "2026-03-04T10:12:26.003587",
  "endpoint": "/api/scrape",
  "error": "HTTP 403: {\"detail\":\"Not authenticated\"}",
  "status_code": 403,
  "latency_ms": 2084.86,
  "backend_url": "http://localhost:8000"
}
```

**Automatically Updated By**:
- `monitor_backend.py` (when errors detected)

**Access**:
```bash
# View raw errors
cat newsai_error_log.json

# View last 10 errors
python -c "import json; errors = json.load(open('newsai_error_log.json')); print('\n'.join(str(e) for e in errors[-10:]))"

# Count errors by endpoint
python -c "import json; errors = json.load(open('newsai_error_log.json')); from collections import Counter; print(Counter(e['endpoint'] for e in errors))"
```

### 4. **monitor_report.json** – Monitoring Report
**Purpose**: Summary of health checks and errors after monitoring run

**Format**: JSON object containing:
- `report_generated`: Timestamp
- `backend_url`: Monitored server
- `total_checks`: Number of checks performed
- `total_errors`: Total errors found
- `status_distribution`: Breakdown of HEALTHY/DEGRADED/CRITICAL
- `recent_checks`: Last 5 health checks
- `errors`: Last 10 errors

**Generated By**:
```bash
python generate_monitor_report.py
# or
python monitor_backend.py --report
```

**Example Usage**:
```bash
# Generate report after demo
python generate_monitor_report.py

# Analyze report
python -c "import json; r = json.load(open('monitor_report.json')); print(f\"Status: {r['status_distribution']}, Errors: {r['total_errors']}\")"
```

## Usage Workflow

### Before Demo
```bash
# 1. Start backend
cd unified_tools_backend
python -m uvicorn main:app --host 0.0.0.0 --port 8000

# 2. (Optional) Start frontend
cd ../blackhole-frontend
npm run dev

# 3. Verify system is ready
python demo_check.py
# Should show: [OK] Demo Status: SAFE

# 4. Start monitoring in background (Terminal 3)
python monitor_backend.py
```

### During Demo
- Keep `monitor_backend.py` running in background terminal
- Watch for status indicators (HEALTHY, DEGRADED, CRITICAL)
- If issue occurs, check `newsai_error_log.json` in real-time
- Refer to DEMO_RECOVERY.md for immediate fixes

### After Demo
```bash
# Generate post-demo report
python generate_monitor_report.py

# Analyze what happened
cat newsai_error_log.json
cat monitor_report.json
```

## Key Metrics Monitored

| Metric | Threshold | Action |
|--------|-----------|--------|

| HTTP 5xx errors | >0 | Logged, status degraded |
| Connection refused | Any | CRITICAL status |

| Response timeout | >10s | Connection issue |
